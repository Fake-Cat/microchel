# docs/PHASE2_PLAN.md — план PHASE 2: Animation Engine

**Цель PHASE 2:** движок анимаций — загрузка кадров в формате VPet (`_NNN_DDD.png`, ADR-005), плеер с per-frame таймингами, loop и переходами, ограниченный кэш ресурсов и приоритетная очередь запросов. Внешний вид: пит в окне проигрывает набор анимаций.

**Команда пользователя:** получена 2026-10-08 («Да, начинаем PHASE 2»).

## Требования

### Функциональные

- **FR-P2.1 Загрузчик кадров:** сканирование каталога анимации, парсинг имён `_{номер:03d}_{длительность_мс}.png` (ADR-005), сортировка по номеру кадра. Битые/чужие имена — пропуск с предупреждением в лог, не крах.
- **FR-P2.2 Анимационный клип:** `AnimationClip` — упорядоченный список кадров с длительностями; один клип = один каталог (`Анимация/Состояние/Линия`); обнаружение линий (1/2/3) с возможностью случайного выбора линии при запуске.
- **FR-P2.3 Плеер:** воспроизведение клипа по таймингам из имён кадров (без внешнего FPS-конфига), `loop=True` (бесконечный) и `loop=False`/N (ограниченный), сигнал на каждый сменённый кадр, остановка и перезапуск без «замерзания».
- **FR-P2.4 Переходы:** запрос новой анимации во время проигрывания — переключение на границе кадра (без разрывов и задержек > длительности текущего кадра); повторный запрос играющей анимации не перезапускает её (есть явный `restart`).
- **FR-P2.5 Приоритетная очередь:** запросы `(приоритет, клип)`; более высокий приоритет прерывает текущую (на границе кадра); после завершения — возврат к предыдущей/idle; одинаковый приоритет — FIFO. Приоритеты: `reaction > event > behavior > idle` (по ARCHITECTURE.md).
- **FR-P2.6 Интеграция с окном:** `PetWindow` показывает текущий кадр плеера вместо статичного спрайта; при кадре другого размера окно меняет размер с сохранением центра (позиция корректируется, драг не «уплывает»).
- **FR-P2.7 Демо-набор анимаций:** генератор `scripts/make_test_animations.py` создаёт свои тестовые клипы (idle, blink, walk — простая геометрия, свой материал) в формате `_NNN_DDD.png`; ассеты VPet не используются (ADR-004).

### Нефункциональные

- **NF-P2.1 Память:** кэш QPixmap с жёстким лимитом (LRU-выгрузка, дефолт ~64 МБ, параметр конструктора); кадры загружаются лениво, выгружаются при вытеснении. При многократных переключениях память не растёт.
- **NF-P2.2 Event loop:** таймер плеера — `QTimer` в главном потоке; чтение каталога — быстрая синхронная операция; ленивая загрузка QPixmap не блокирует event loop надолго. Потоки в PHASE 2 не нужны.
- **NF-P2.3 Тестируемость:** парсер имён, LRU-кэш, очередь приоритетов, логика таймингов — чистые без Qt-событий (юнит); плеер и окно — pytest-qt (offscreen).
- **NF-P2.4 Портативность:** только PySide6 + stdlib, без x86-64-only зависимостей.
- **NF-P2.5 Производительность:** смена кадра без лишних аллокаций; отрисовка — существующий `paintEvent`.

### Явно НЕ входит в PHASE 2

FSM и автономное поведение (PHASE 3), внешность/эмоции/костюмы (PHASE 4), события character → player (только прямые вызовы), звук, моды и загрузка ассетов VPet, конвертеры изображений, кэш на диск.

## Архитектура (структура кода)

```
src/microchel/animation/
├── frames.py    # чистое: parse_frame_name(), load_clip(dir) → AnimationClip
├── cache.py     # чистое: FrameCache — LRU по байтам, purge/evict
├── player.py    # Qt: AnimationPlayer(QObject) — QTimer, смена кадров, сигнал frame_changed
└── queue.py     # чистое: приоритетная очередь запросов (priority, clip)
```

Интеграция: `PetWindow(animation_root)` → создаёт `AnimationPlayer`, подписывается на `frame_changed` → `update()`; меню/драг не трогаем. Демо-клипы: `assets/characters/test/<Анимация>/<Состояние>/<Линия>/_NNN_DDD.png`.

## План шагов

1. **Документы**: этот план, обновить ROADMAP (PHASE 2 → текущий), STATUS (точка возобновления).
2. **Генератор тестовых анимаций**: `scripts/make_test_animations.py` → idle/blink/walk в формате `_NNN_DDD.png` (длительности 125/250/375 мс).
3. **`frames.py`**: парсинг имени кадра (regex), `load_clip` (сканирование, сортировка, линии), ошибки — в лог.
4. **`cache.py`**: LRU-кэш QPixmap с лимитом байт, `get/load/evict/purge`, счётчики хитов/промахов.
5. **`queue.py`**: приоритетная очередь запросов, `next()/finish()/current`, FIFO внутри приоритета.
6. **`player.py`**: `play(clip, loop, restart)`, таймер по длительности кадра, сигнал `frame_changed(QPixmap)`, возврат в очередь по завершении, прерывание по приоритету.
7. **Интеграция `PetWindow`**: подключение плеера, автоподстройка размера под кадр с сохранением центра, fallback на статичный спрайт если анимаций нет.
8. **Тесты**: юнит (frames/cache/queue/тайминги) + pytest-qt интеграция (плеер, окно); eviction кэша, 1000 переключений без роста.
9. **Проверка памяти**: ручной замер RSS при ≥ 10 мин проигрывания (итог в TESTING.md).
10. **Документация + коммит**: STATUS/ROADMAP/ARCHITECTURE/DEVELOPMENT_LOG/CHANGELOG/TESTING.

## Риски

- Без ассетов VPet (ADR-004) демо-кадры примитивны — «красота» появится в PHASE 4; здесь важна механика.
- Кадры разного размера у разных анимаций — автоподстройка окна может «прыгать» центром во время драга; решение: подстраивать только при смене размера кадра, центр держать.
- RSS-замер на dev-стенде грубый (память Python шумит) — юнит-тест eviction + ручной замер, без юнит-тестов «на утечки» (flaky).
