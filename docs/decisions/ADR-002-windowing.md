# ADR-002: Оконный протокол — X11 предпочтителен, Wayland подлежит проверке

**Статус:** принят, **уточнён по факту в PHASE 1 (2026-10-08)** — см. «Результаты проверки».

## Контекст

Концепция требует frameless-окно с alpha-прозрачностью и always-on-top. Целевая среда (Raspberry Pi OS) — X11. Фактическая dev-сессия на Ubuntu 26.04 оказалась **Wayland** (`XDG_SESSION_TYPE=wayland`), XWayland доступен (`DISPLAY=:0`).

## Рассмотренные альтернативы

- **Только X11**: на dev-стенде Wayland — пришлось бы менять сессию (запрещено без согласования).
- **Только Wayland**: целевая RPi — X11, значит и Wayland нельзя делать единственным.
- **Поддержка обоих**: Qt сам выбирает бэкенд; риски Wayland isolируются в одном месте (окно).

## Решение

Приложение не привязан к протоколу жёстко: используем штатные средства Qt (`Qt.WindowFlags`, `WA_TranslucentBackground`). Порядок проверки в PHASE 1: Wayland (нативный) → XWayland → X11. Факт и результаты проверки зафиксировать здесь и в TESTING.md.

## Причины

- Не менять системную конфигурацию без согласования.
- Целевая платформа X11 должна работать в любом случае.

## Последствия

- На Wayland always-on-top может не работовать (GNOME не поддерживает X11-трюки для нативных wayland-окон; частично решается XWayland).
- Возможна необходимость флага `QT_QPA_PLATFORM=xcb` на Wayland-стенде — это настройка приложения, не системы.

## Результаты проверки (PHASE 1, 2026-10-08)

Проверено на Ubuntu 26.04 / GNOME / Wayland, Qt 6.12.0, пользователь вручную:

| Режим | Результат |
|---|---|
| Wayland (нативный) | Окно видно, **прозрачность работает**, события мыши доходят (689 записей в логе), но **перетаскивание невозможно**: композитор игнорирует `move()` клиента — позиция окна не меняется. Подтверждено логом: «ЛКМ нажата» есть, координаты позиции статичны. |
| XWayland (`QT_QPA_PLATFORM=xcb`) | **Драг работает** — подтверждено пользователем вручную. Требуется системный пакет `libxcb-cursor0` (Qt ≥ 6.5 не грузит xcb без него). |
| X11 (целевая RPi) | Ожидание: работает как xcb (проверить в PHASE 10). |

**Итоговое решение:** под Wayland-сессией приложение **по умолчанию запускается через XWayland (xcb)** — авто-выбор в `select_qt_platform()` (`src/microchel/desktop/main.py`), явно заданный `QT_QPA_PLATFORM` не перетирается. Системная конфигурация Wayland не менялась (требование AGENTS.md выполнено).

## Ограничения

- xcb под Wayland — временный путь: XWayland развивается медленнее нативного Wayland; если GNOME в будущем сломает XWayland — пересмотреть (варианты: layer-shell, позиционирование через диалоги). Перепроверить при обновлении Qt/Ubuntu.
- `libxcb-cursor0` — новая системная зависимость (согласована пользователем, установлена 2026-10-08); учесть в README для других машин.
