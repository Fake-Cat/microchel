# AGENTS.md — инструкции для агента разработки

Постоянные правила проекта **Microchel (Микрочел)**. Новый сеанс обязан прочитать этот файл первым, затем `docs/PROJECT.md`, `docs/STATUS.md`, `docs/ROADMAP.md`, последние записи `docs/DEVELOPMENT_LOG.md` и выполнить `git status`.

## 1. Цель проекта

Linux-приложение: анимированный Desktop Pet (аналог VPet-Simulator) с автономным ИИ-агентом. Персонаж живёт на рабочем столе (ходит, спит, ест, реагирует), выполняет поручения на естественном языке через LLM и инструменты, мониторит систему, работает 24/7. Полная концепция: `docs/concept.md`.

## 2. Архитектурные ограничения

- Модульная архитектура: desktop, animation, character (FSM), agent, tools, voice, monitoring, memory (SQLite), common (event bus, config).
- GUI не связывается напрямую с LLM и инструментами — только через Agent Core.
- Долгие операции не блокируют Qt event loop (отдельные потоки/процессы).
- Опасные системные операции и доступ к секретам — только через Permission policy с подтверждением.
- Мониторинг и память работают без LLM; сбой API не останавливает пета.
- Понятная архитектура без микросервисов и лишних фреймворков.

## 3. Совместимость (x86-64 и ARM64)

- Среда разработки: Ubuntu 26.04 x86-64 (ThinkPad). Целевая: Raspberry Pi 4B, 4 GB RAM, ARM64, Raspberry Pi OS, X11.
- Запрещены x86-64-only бинарные зависимости без альтернативы для ARM64 (проверять wheels/пакеты для aarch64).
- Никакого Electron/Chromium/CUDA. Минимум RAM/CPU в IDLE, кэширование ресурсов.
- Не предполагать X11: проверять `XDG_SESSION_TYPE` (разработка идёт и под Wayland).

## 4. Правила разработки

- Python type hints, читаемый код, структурированное логирование, явная обработка исключений.
- pytest + Ruff; конфигурация в `pyproject.toml`.
- Небольшие логические итерации; не маскировать ошибки заглушками; не выдавать временные решения за готовые.
- Зависимости — воспроизводимо, минимум лишнего. Конфигурация вне кода.
- Не менять архитектуру без явной необходимости; существенные изменения — через ADR в `docs/decisions/` и согласование с пользователем.
- Идентификаторы — на английском, документация и отчёты — на русском.

## 5. Порядок работы (каждый сеанс)

1. Прочитать AGENTS.md, docs/PROJECT.md, docs/STATUS.md, docs/ROADMAP.md, последние записи docs/DEVELOPMENT_LOG.md.
2. `git status` — определить незавершённую работу.
3. Перед изменениями: изучить код, сформулировать план, определить файлы и способ проверки.
4. После итерации: запустить проверки, зафиксировать реальные результаты, обновить STATUS.md, DEVELOPMENT_LOG.md, ROADMAP.md.
5. Предложить следующее конкретное действие. Не начинать новый этап без команды пользователя.

## 6. Тестирование

- Запуск: `python -m venv .venv && source .venv/bin/activate && pip install -e ".[dev]" && pytest`.
- GUI-сценарии — вручную по `docs/TESTING.md`; автоматика — pytest/pytest-qt.
- Если тест не запускался — прямо указать это. Не отмечать задачу выполненной без оснований.

## 7. Безопасность

- Не выдавать модели произвольный shell по умолчанию.
- Удаление данных, изменение системной конфигурации, повышение привилегий — только с подтверждением.
- Секреты — в `.env` (не коммитится), в логи не выводить.
- Учитывать prompt injection в недоверенных данных.

## 8. Git

- Небольшие логические коммиты с понятными сообщениями; документация — вместе с кодом.
- Не коммитить: секреты, `.venv`, кэши, временные файлы, чужие графические материалы без проверки лицензии.
- Не делать force push и не переписывать историю без согласования.
- Автокоммиты — только если пользователь поручил.

## 9. Лицензии сторонних материалов

- Код VPet — Apache-2.0; анимации VPet — отдельные условия (некоммерческое использование с указанием источника и ссылки на репозиторий). Подробности: `docs/RESEARCH_VPET.md`.
- Не включать в репозиторий материалы с неустановленными правами. Перед добавлением любых чужих ресурсов — проверить лицензию и записать её в `docs/RESEARCH_VPET.md`.

## 10. Запреты

- Не устанавливать системные пакеты и не менять конфигурацию X11/Wayland без согласования.
- Не реализовывать агента, голос и мониторинг вне своих этапов (PHASE 5+).
- Не удалять историю разработки (`DEVELOPMENT_LOG.md`) ради сокращения контекста.
