# ADR-003: Отдельное Agent Core, не связанное с GUI

**Статус:** принят (2026-10-08)

## Контекст

Концепция: GUI не должен быть связан напрямую с LLM и реализацией инструментов; долгие задачи не блокируют Qt event loop; сбой API не должен останавливать пета.

## Рассмотренные альтернативы

- **LLM-вызовы прямо из GUI-кода**: просто, но блокирует event loop, нарушает требования, ломает тесты.
- **Отдельные процессы/микросервисы для каждого компонента**: избыточно для Raspberry Pi 4 GB, противоречит «понятной архитектуре без микросервисной сложности».
- **Единый процесс, агент в фоновых потоках + чёткий слой agent/**: баланс простоты и требований.

## Решение

Agent Core — отдельный слой `src/microchel/agent/` со своим API (запуск задачи, статусы, отмена). GUI общается с ним только через события common/event_bus и не знает о провайдерах/инструментах. Долгие вызовы — в `QThread`/пуле; инструменты выполняются с таймаутами. Мониторинг и память не зависят от агента.

## Причины

- Тестируемость: GUI, FSM и Agent Core проверяются независимо.
- Устойчивость: падение LLM-API не влияет на отображение и мониторинг.

## Последствия

- Нужен явный формат событий и статусов (уточнить в PHASE 3/5).
- Немного больше кода на «клей» между слоями.

## Ограничения

- В одном процессе краш нативных расширений Qt всё ещё уронит всё — crash recovery в PHASE 9.
