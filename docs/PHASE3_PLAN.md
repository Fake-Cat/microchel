# docs/PHASE3_PLAN.md — план PHASE 3: Character Behavior

**Цель PHASE 3:** FSM поведения персонажа — состояния `idle/walk/sleep/sit/coffee/thinking`, автономный выбор следующего действия (веса + время суток, настраиваемые в конфиге), события пользователя (клик/драг) и системные события (типы событий + источник-заглушка до PHASE 7). Ходьба двигает окно по экрану. Критерий ROADMAP: персонаж сам ведёт себя естественно ≥ 10 мин без вмешательства.

**Команда пользователя:** получена 2026-10-08 («Да, начинаем PHASE 3: составить план…»).

## Требования

### Функциональные

- **FR-P3.1 Состояния (FSM):** `CharacterState` — IDLE, WALK, SLEEP, SIT, COFFEE, THINKING. Маппинг состояние → клип (`Idle/Walk/Sleep/…`) и приоритет (`BEHAVIOR`); отсутствующий клип → состояние пропускается с предупреждением в лог (деградация без краха). WAKE/эмоции — PHASE 4.
- **FR-P3.2 Автономный выбор:** по истечении срока состояния FSM выбирает следующее по весам (walk чаще, sleep реже); ночью (интервал в конфиге) вес SLEEP резко выше. Случайность — через `random.Random` (seed в тестах → детерминизм).
- **FR-P3.3 Тайминги из конфига:** `config/behavior.toml` (tomllib, stdlib) — паузы idle, длительности состояний, веса, ночь, шаг ходьбы. Нет файла/битые значения → дефолты + предупреждение (не крах).
- **FR-P3.4 Ходьба двигает окно:** пока FSM в WALK, контроллер шагает окно на `walk_step_px` каждые `walk_interval_ms` через существующий `move_clamped`; упёрлись в край (позиция не изменилась) → разворот. Максимум — зажим в `desktop_area()` (уже есть).
- **FR-P3.5 События пользователя:** клик (ЛКМ без смещения) → реакция `REACTION` (blink) поверх текущего состояния; состояние FSM при этом не меняется — после окончания реакции текущее состояние возобновляется. Драг → немедленное прерывание WALK в IDLE (пит «в руках у пользователя»).
- **FR-P3.6 Системные события:** тип `SystemEvent` в `common/events.py`; до PHASE 7 источник — только синтетический (флаг `--demo-events`, раз в 45–90 с) для проверки механики; обработка — приоритет `EVENT`.
- **FR-P3.7 Событийная шина:** минимальный `common/event_bus.py` (синхронный subscribe/emit, главный поток) + типы событий `common/events.py` (`UserEvent`, `SystemEvent`, `CharacterAction`) — схема из ARCHITECTURE.md фиксируется в этом PHASE.
- **FR-P3.8 Интеграция:** `main.py` собирает controller (окно + плеер + bus), включает поведение по умолчанию при наличии клипов; `--demo` (PHASE 2) остаётся отладочным режимом и **отключает** FSM (взаимоисключающие режимы, логируется).

### Нефункциональные

- **NF-P3.1 Тестируемость:** FSM, конфиг, веса, логика разворота — чистые без Qt (юнит); controller — pytest-qt (offscreen) с колбэками-заглушками.
- **NF-P3.2 Event loop:** вся логика — QTimer в главном потоке, никаких потоков; тики дешёвые (не чаще 1 раза в ~100 мс).
- **NF-P3.3 Память/CPU:** поведение — 1–2 таймера; RSS не растёт за ≥10 мин (замер, как в PHASE 2).
- **NF-P3.4 Портативность:** только PySide6 + stdlib (tomllib, random, datetime), без x86-only зависимостей.
- **NF-P3.5 Отсутствие анимаций/конфига** → поведение молча не запускается (окно как в PHASE 1), ошибки — в лог.

### Явно НЕ входит в PHASE 3

Эмоции/костюмы/внешность и WAKE (PHASE 4); LLM/агент и связка THINKING с задачами (PHASE 5); реальный monitoring и события ОС (PHASE 7 — здесь только типы событий и синтетический источник); голос, память, уведомления, звук.

## Архитектура (структура кода)

```
src/microchel/common/
├── events.py       # чистое: UserEvent, SystemEvent, CharacterAction (frozen dataclass)
└── event_bus.py    # чистое: мини event bus (subscribe/emit/clear), главный поток
src/microchel/character/
├── states.py       # чистое: CharacterState (StrEnum) + маппинг состояние → (клип, приоритет)
├── config.py       # чистое: BehaviorConfig + загрузка config/behavior.toml (tomllib)
├── fsm.py          # чистое: BehaviorFSM — тайминги, веса, ночь, on_event(); принимает Random
└── controller.py   # Qt-клей: таймер состояния и шага ходьбы, подписка на bus,
                    # колбэки play(clip, priority, loop) / move(dx) / bounds()
config/behavior.toml
```

Поток событий: `PetWindow` (клик/драг) → `event_bus.emit(UserEvent)` → `CharacterController` → `fsm.on_event()` → смена состояния → колбэк `play(...)` в плеер / `move(dx)` в окно. FSM ничего не знает про Qt и плеер.

## План шагов

1. **Документы**: этот план; после согласования — ROADMAP (PHASE 3 → текущий), STATUS (точка возобновления).
2. **`common/events.py` + `common/event_bus.py`**: типы событий и шина + юнит-тесты.
3. **`character/states.py`**: enum + маппинг; юнит-тесты (все состояния → клипы, деградация).
4. **`character/config.py` + `config/behavior.toml`**: дефолты, загрузка, битые значения → дефолт; юнит-тесты.
5. **`character/fsm.py`**: таймеры состояний, весовой выбор (seeded Random), ночь, `on_event`; юнит-тесты (достижимость всех состояний, ночь → SLEEP, событие прерывает WALK).
6. **`character/controller.py`**: QTimer-тик, смена состояния → play/move, шаг ходьбы с разворотом у края, подписка на bus, восстановление состояния после реакции.
7. **Генератор ассетов**: расширить `scripts/make_test_animations.py` — клипы Sleep/Sit/Coffee/Thinking (свой материал, формат `_NNN_DDD.png`).
8. **Интеграция**: `window.py` — клик (без смещения) и драг → события в bus; `main.py` — сборка controller, флаги `--demo` (отключает FSM) и `--demo-events`.
9. **Тесты**: юнит (states/config/fsm/разворот) + интеграция pytest-qt (controller с заглушками: тик → play, клик → REACTION, восстановление после реакции).
10. **Ручная проверка**: сценарии P3-1…P3-7 в TESTING.md, наблюдение ≥10 мин, RSS-замер.
11. **Документация + коммит**: ARCHITECTURE (схема событий и модель состояний — «уточнено в PHASE 3»), STATUS/ROADMAP/DEVELOPMENT_LOG/CHANGELOG/TESTING.

## Критерии готовности PHASE 3

- [ ] `pytest` зелёный (юнит + интеграция), `ruff check .` без ошибок.
- [ ] Персонаж ≥ 10 мин автономно проходит состояния (idle → walk/sit/coffee/thinking/sleep и обратно) без вмешательства — подтверждено пользователем (лог переходов в `/tmp/microchel_gui.log`).
- [ ] Ходьба двигает окно, разворачивается у краёв, не выходит за `desktop_area()`.
- [ ] Клик → краткая реакция с возвратом к текущему состоянию; драг прерывает ходьбу.
- [ ] Синтетическое системное событие (`--demo-events`) обрабатывается с приоритетом EVENT.
- [ ] RSS стабилен за ≥10 мин (замер в TESTING.md).
- [ ] Документация обновлена (ARCHITECTURE — схема событий), всё закоммичено.

## Риски

- **Естественность поведения субъективна** — веса/интервалы вынесены в `config/behavior.toml`, подстройка итерациями при ручной проверке P3-1.
- **Движение окна под Wayland** — работает только под xcb (ADR-002, авто-выбор уже есть); нативный wayland в тестах не проверяется.
- **Offscreen-тесты не видят реальный `move()`** — логика разворота покрыта юнит-тестами (позиция «не изменилась» → разворот), реальное движение — ручной сценарий.
- **Конфликт режимов `--demo` и FSM** — решено: `--demo` отключает поведение (FR-P3.8); прежние сценарии P2 сохраняются.
