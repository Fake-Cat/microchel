# docs/TESTING.md — стратегия тестирования

## Стратегия

- **Юнит-тесты** (pytest): логика без GUI — FSM, парсер кадров, event bus, конфиг, инструменты агента.
- **GUI-тесты** (pytest-qt): виджеты и ввод, по возможности без реального дисплея.
- **Ручные сценарии** (таблица ниже): визуальные проверки прозрачности, always-on-top, перетаскивания.
- **Ресурсные тесты**: стабильность памяти при длительном проигрывании (здесь dev-стенд врёт — см. ограничения).

## Команды запуска

```bash
cd /home/fake-cat/projects/microchel
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
pytest              # все тесты
pytest tests/unit   # только юнит
ruff check .        # линтер
```

Для headless-запуска GUI-тестов (когда появятся) — поставить `xvfb` (apt, требует согласования) и запускать под `xvfb-run -a pytest`.

Для визуального просмотра всех анимаций по очереди: `python -m microchel.desktop.main --showcase` — каждый клип по `--showcase-interval` с (по умолчанию 10), цикл повторяется; FSM отключён. Воспроизведение идёт по playback-спеке `assets/characters/<персонаж>/clips.toml`, как в рантайме: once-клипы играются один раз, loop-сегмент [a, b] крутится по кругу весь слот, `repeat_fill_ms` даёт случайное число повторов (не дольше слота), `mirror="left"` показывает кадры зеркально, `motion=walk/traverse` двигает окно во время клипа. Список клипов и спека перечитываются на каждом тике — персонажа можно менять через контекстное меню прямо во время показа.

## Известные ошибки

1. **Неплавность вертикального движения** (замечание пользователя 2026-10-08): дыхание в idle и покачивание в walk ступенчатые (кадры 250 мс, смещения 2–4 px). Механика верна, плавность низкая. Варианты улучшения: больше кадров с меньшими интервалами, интерполяция позиции между кадрами. **План: PHASE 4 (внешность/качество) либо отдельной задачей.**
2. P2-5 (память ≥10 мин): замер выполнен на 6-минутном интервале — RSS 103080 → 104356 kB, после первой минуты роста нет (89 переключений демо). Окно продолжает работу в фоне — при желании замер продолжается.
3. **«Резкое пробуждение на секунду» (наблюдение пользователя 2026-10-08):** ночью поверх сна системное событие (`--demo-events`) проигрывает клип Blink (~570 мс) **стоячей позой** (в тестовом ассете blink есть только стоя) — визуально пит резко «встаёт» и снова ложится. Сон FSM не прерывается, состояние не меняется. План: PHASE 4 — лежачий вариант blink либо пауза реакций во время сна.
